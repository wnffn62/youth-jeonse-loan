# 청년 전세대출 진단

20대가 자기 조건(소득·재직상태·신용점수·보증금)을 넣으면 신청 가능한 전세대출 상품과 예상 금리·한도를
계산하는 프로그램이다. 제도가 바뀌면 자동으로 감지해 보고서를 만들고, 계층에 따라 반영한다.

## 구성

| 경로 | 역할 |
| --- | --- |
| `index.html` | 진단 화면. 규칙 엔진을 포함하며, 데이터를 직접 담지 않는다 |
| `data/policies.json` | 제도 데이터 정본. 상품·요건·금리표·한도·출처 |
| `data/policies.js` | 화면이 읽는 사본. `update_policies.py` 가 정본에서 자동 생성한다 |
| `data/sources.json` | 변경을 감시할 공식 출처 목록 |
| `tools/update_policies.py` | 변경 감지·반영기 |
| `tools/validate_data.py` | 데이터 정합성 검사기 |
| `tools/자동점검_등록.ps1` | 작업 스케줄러 등록·해제 |
| `_work/` | 스냅샷·보고서·상태. 외부 배포 대상이 아니다 |

화면과 데이터를 분리한 이유는 제도가 바뀔 때 `policies.json` 한 파일만 고치면 되게 하기 위해서다.
화면 코드를 건드리지 않으므로 갱신에서 새 결함이 생길 여지가 작다.

## 실행

```
index.html 을 브라우저로 연다
```

별도 서버가 필요 없다. `data/policies.js` 를 스크립트로 읽으므로 `file://` 에서도 동작한다.

## 자동 반영 구조

제도 변경을 **감지**하는 일과 화면에 **반영**하는 일을 분리했다.
감지는 전량 자동으로 수행하고, 반영은 오판의 손해 크기에 따라 게이트를 다르게 둔다.

| 계층 | 대상 | 감지 | 반영 |
| --- | --- | --- | --- |
| A `auto` | 공개 API 응답 | 자동 | 자동 |
| B `review` | 공식 HTML 고시(금리표·요건) | 자동 | 확정 대기 후 사람이 반영 |
| C `signal` | 보도자료 목록 | 자동 | 알림만 |

금리·소득요건을 자동 반영하지 않는 근거는 다음과 같다.

- 정부 사이트의 HTML 구조는 예고 없이 바뀐다. 파서가 깨진 것을 감지하지 못하면 잘못 읽은 값이 그대로 화면에 나간다.
- 전세대출 금리는 이용자의 실제 금전 부담을 결정한다. 잘못된 금리를 보고 계약하면 회복이 어렵다.
- 따라서 **변경 사실은 100% 자동으로 알리되, 수치 확정은 사람이 한다.** 확정 전까지 화면 상단에
  「변경 감지 N건 확정 대기」를 표시해 이용자가 원문을 확인하도록 유도한다.

또한 화면은 항상 제도 기준일을 노출하고, 기준일이 설정값(기본 90일)을 넘기면 경고 배지를 띄운다.

### 명령

```
python tools/update_policies.py --init     최초 스냅샷 생성
python tools/update_policies.py --check    변경 감지 후 보고서 생성
python tools/update_policies.py --apply    감지 후 A계층까지 반영
python tools/validate_data.py              데이터 정합성 검사
```

종료코드는 `update_policies.py` 가 변경 감지 시 1, `validate_data.py` 가 경고 1·오류 2를 돌려준다.
배포 전에는 `validate_data.py` 가 0 또는 1을 돌려주는지 확인한다.

### 예약 실행

```
powershell -ExecutionPolicy Bypass -File tools\자동점검_등록.ps1
powershell -ExecutionPolicy Bypass -File tools\자동점검_등록.ps1 -Remove
```

기본값은 매주 월요일 09:10이다. `-Cycle Daily -Time "09:00"` 으로 바꿀 수 있다.
배터리 구동 중에도 실행되도록 설정한다. 배터리 전환으로 예약 작업이 정지된 이력이 있어서다.

## 판정 엔진

`policies.json` 의 각 상품은 선언적 규칙 배열을 가진다. 화면은 이 규칙을 해석만 한다.

```json
{ "field": "householdIncome", "op": "lte", "value": 5000,
  "label": "부부합산 연소득 5천만원 이하", "hard": true }
```

- `hard: true` 미충족 시 탈락으로 처리하고 사유를 표시한다.
- `hard: false` 경고로만 표시한다.
- 입력이 비어 있으면 「확인 필요」로 분류한다. 모르는 값을 통과로 처리하지 않는다.

금리는 `rate_table` 에서 소득·보증금·지역 조건이 가장 많이 명시된 행을 고른다.
우대금리는 기본 금리에서 자동으로 빼지 않고 별도 목록으로 보여 준다. 중복 적용 한도가 상품마다 달라서다.

## 데이터 원칙

- 모든 상품에 `source.url` 과 `source.asof` 기준일을 둔다. 출처 없는 수치는 넣지 않는다.
- 원문에서 확인하지 못한 값은 비워 두고 `confidence: "unverified"` 로 표시한다. 추정으로 메우지 않는다.
- 종료·일몰된 상품은 지우지 않고 `status` 에 표시한다. 이용자가 「그 상품은 왜 없나」를 묻지 않게 하기 위해서다.

## 한계

- 실제 승인 여부·한도·금리는 은행과 보증기관 심사에서 정해진다. 이 프로그램의 결과는 참고용 추정치다.
- 신용점수는 이용자 입력값에 의존한다. 은행이 조회하는 점수와 다를 수 있다.
- 지자체 사업은 연도별 공고에 따라 바뀌므로 공고 기간을 별도로 확인해야 한다.

## 공개 주소와 자동 갱신

- 공개 페이지: https://wnffn62.github.io/youth-jeonse-loan/
- 저장소: https://github.com/wnffn62/youth-jeonse-loan

매주 월요일 09:00(KST) 예약 클라우드 에이전트가 `tools/ROUTINE.md` 절차를 수행한다.
공식 출처를 점검해 변경을 감지하고, 바뀐 페이지를 직접 읽어 수치를 추출한 뒤
안전장치 4종을 통과한 항목만 반영하고 `push` 한다. `push` 하면 Pages 가 공개 페이지를
자동 갱신하므로 별도 배포 단계가 없다. PC 전원 상태와 무관하게 실행된다.

`tools/자동점검_등록.ps1` 은 같은 점검을 로컬에서 돌리는 예비 경로다. 클라우드 루틴과
중복 실행해도 스냅샷 비교 결과가 같으므로 충돌하지 않는다.
