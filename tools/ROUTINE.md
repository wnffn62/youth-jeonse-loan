# 주간 자동 점검 지시서

예약 클라우드 에이전트가 매주 이 문서를 읽고 수행한다.

이 저장소는 20대에게 전세대출 상품·금리·한도를 안내하는 공개 웹앱이다
(https://wnffn62.github.io/youth-jeonse-loan/).
잘못된 금리가 표시되면 이용자가 그 금리를 믿고 계약해 금전 피해를 볼 수 있다.
**확실하지 않으면 반영하지 말고 보류한다.** 보류는 안전하고, 잘못된 반영은 되돌릴 수 없다.

---

## 1단계 준비

```
python -m pip install --quiet requests beautifulsoup4
python tools/update_policies.py --check
```

표준출력에 출처별 `[동일]` `[변경]` `[실패]` `[빈본문]` 이 나온다.
`_work/reports/` 의 최신 HTML 보고서도 읽는다.

**변경도 실패도 없으면**: 아무것도 고치지 않고 「변동 없음」만 보고하고 끝낸다. 커밋하지 않는다.

**실패만 있고 변경이 없으면**: 해당 출처의 URL이 바뀐 것이다. 3단계로 건너뛰어 새 URL을 찾는다.

## 2단계 변경된 출처를 직접 읽는다

`[변경]` 으로 표시된 출처마다 `data/sources.json` 의 url 을 WebFetch 로 열어
**의미 기준으로** 현재 값을 읽는다. 정규식 추출에 의존하지 않는다.
정부 사이트는 HTML 구조가 예고 없이 바뀌지만, 「소득 2천만원 이하 구간의 금리」라는
의미는 유지된다. 페이지를 읽어서 이해하는 방식이 구조 변경에 견딘다.

상품마다 확인할 값:

- 연령 요건, 부부합산 소득 상한, 순자산 상한
- 임차보증금 상한, 전용면적 상한
- 대출한도, 보증금 대비 대출비율
- **소득구간별 금리표 전체** (지역별 인하폭 포함)
- 우대금리 항목과 폭, 우대 적용 상한
- 대출기간, 취급은행
- 운영 여부 (종료·일몰·신규 취급 중단 포함)

## 3단계 교차검증

같은 수치를 **독립된 출처 2곳 이상**에서 확인한다. 호스트가 달라야 독립으로 센다.

| 대상 | 교차 출처 조합 |
| --- | --- |
| 기금 상품 금리·요건 | 주택도시기금 상품 페이지 + 취급은행 안내 페이지 |
| 은행 금리 | 은행 공식 상품 페이지 + 금융감독원 비교공시 또는 은행연합회 소비자포털 |
| 보증 한도·보증료율 | 한국주택금융공사 페이지 + 주택도시기금 보증 종류별 안내 |
| 지자체 사업 | 지자체 공식 포털 + 해당 연도 공고문 |

두 곳의 값이 다르면 **반영하지 않고** 보류 사유에 양쪽 값을 함께 적는다.

URL 이 응답하지 않으면 공식 사이트에서 같은 상품을 다시 찾아 새 URL 을 확인하고,
`data/sources.json` 의 url 을 고친다. 경로 수정은 안전하므로 바로 반영한다.

## 4단계 추출 결과 작성

`tools/_extracted.json` 을 아래 형식으로 쓴다.
**확인한 값만 넣는다. 못 읽은 필드는 아예 빼라.** 빈 값이나 추정값을 넣으면 안 된다.

```json
{
  "extracted_at": "2026-10-05",
  "products": [
    {
      "id": "beotimmok_youth",
      "sources_agreeing": ["https://nhuf.molit.go.kr/...", "https://...다른호스트..."],
      "anchors_found": ["부부합산", "순자산", "전용면적", "임차보증금", "신용도"],
      "rate_table": [
        { "income_max": 2000, "regions": ["seoul", "metro"], "rate": 2.2, "label": "연소득 2천만원 이하 · 수도권" }
      ],
      "limit": { "max": 15000, "deposit_ratio": 0.8 },
      "status": "운영중",
      "asof": "2026-10-05"
    }
  ]
}
```

- `id` 는 `data/policies.json` 의 기존 id 와 정확히 일치해야 한다. 새 상품은 자동 반영되지 않는다.
- `anchors_found` 는 페이지에서 **실제로 본** 라벨만 적는다. 여기에 없는 라벨을 적으면 앵커검사가 무의미해진다.
- `regions` 값은 `seoul` `metro` `metro_city` `other` 네 가지만 쓴다.
- 금액은 만원 단위, 금리는 연 % 숫자다.

## 5단계 안전장치 통과 후 반영

```
python tools/apply_extraction.py --input tools/_extracted.json
python tools/validate_data.py
```

`apply_extraction.py` 가 네 가지를 검사한다.

1. **교차검증** 독립 출처 2곳 이상
2. **앵커검사** 선언된 불변 라벨이 모두 확인됐는지
3. **변동폭** 금리 ±1.0%p, 한도 ±30%, 금리표 행 수 ±2 이내
4. **사후검증** 반영 뒤 정합성 검사 실패 시 자동 롤백

보류된 항목은 표준출력에 사유와 함께 나온다. **보류를 우회하려고 임계값을 고치지 마라.**
임계값을 넘는 변동은 제도가 크게 바뀌었거나 추출이 틀렸다는 신호다. 보고서에 적고 사람 판단에 맡긴다.

`validate_data.py` 종료코드는 0 통과, 1 경고, 2 오류다. **2면 커밋하지 않는다.**

## 6단계 커밋과 배포

반영된 변경이 있고 `validate_data.py` 가 0 또는 1이면 커밋하고 push 한다.

```
git add data/ tools/_extracted.json
git commit -m "제도 변경 반영 YYYY-MM-DD"
git push
```

push 하면 GitHub Pages 가 자동으로 공개 페이지를 갱신한다. 별도 배포 작업은 없다.

`tests/engine_test.cjs` 가 있으면 커밋 전에 `node tests/engine_test.cjs` 를 실행한다.
금리표 구조가 바뀌면 이 테스트가 먼저 깨진다. 깨지면 커밋하지 말고 보고한다.

push 가 권한 문제로 실패하면 변경 내용을 보고서에 전부 적어 사람이 수동 반영할 수 있게 한다.

## 7단계 보고

마지막에 아래를 보고한다.

- 점검한 출처 수, 변경 감지 건수, 반영 건수, 보류 건수
- 반영한 항목의 이전 값과 새 값
- 보류한 항목과 사유 (어느 안전장치에 걸렸는지)
- URL 을 고친 출처
- 사람이 판단해야 할 사항

## 하지 말 것

- 확인하지 못한 수치를 추정으로 채우는 것
- 보류를 피하려고 안전장치 임계값을 완화하는 것
- 한 출처만 보고 금리를 바꾸는 것
- 1회 요청 실패를 상품 폐지로 해석하는 것 (기금포털은 산발적으로 요청이 실패한다)
- `data/policies.json` 의 `source.confidence` 를 근거 없이 올리는 것
- 조사 과정·도구 실패 기록을 `data/` 에 남기는 것 (`_work/` 는 git 제외 대상이다)
